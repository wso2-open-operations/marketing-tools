# Project structure review: Amplify in marketing-tools

Date: 2026-10-26 · Method: WSO2 Digital project-structure conventions · Scope: `projects/marketing-tools` (root files, `apps/amplify` tree, docs placement, `local/`, `scripts/`, Dockerfile and Choreo descriptor placement, naming), `projects/one-wso2/webapp/src/features/amplify`, and the people-app and po-agent changes. Re-run of the 19 Oct review after the 20 Oct flattening and the 26 Oct move of `architecture/` and `docs/` into `apps/amplify`.

**Overall:** still conforms on the things that matter for review and operation. Every Ballerina deployable has a `CLAUDE.md`, a committed `Dependencies.toml` and `observabilityIncluded = true`. Every component has its own Dockerfile, `.choreo/component.yaml` and `workload.yaml`, and `scripts/check-descriptors.sh` keeps them in step. Every relative link in `apps/amplify/**/*.md` resolves, and none points outside `projects/`. The new problems come mostly from drift: the `apps/amplify/README.md` layout block is stale after the move, the new `architecture/` and `docs/` trees are untracked and use names with spaces, and a few project docs still describe the old workspace layout.

## Placement of `architecture/` and `docs/` under `apps/amplify`

The skill's repo layout has no `architecture/` folder and no repo-level `docs/`. It names three doc locations: `docs/migrations/` for dated change notes, `.claude/` for internal Claude docs, and a `CLAUDE.md` and README per service. It says nothing against app-level doc folders.

What fits:

- **Per-app, not repo-root.** marketing-tools is a shared repo. `conference` and `registrant` have no `docs/` or `architecture/`. Putting Amplify's 37 ADRs, threat model and plan at the repo root would mix them with other apps and force `ADR-NNN` numbers to be shared. Under `apps/amplify` the numbering stays Amplify's. Keep them there.
- **`docs/migrations/` is where the skill wants it.** Keep it.
- **Links stay relative and resolve.** Docs, ADRs, runbooks and component READMEs cross-link without leaving the app.

What I would change:

1. **Keep `architecture/` at the app root, and put everything else under `docs/`.** Today `docs/` holds six kinds of file (runbooks, reviews, research, security exceptions, test notes, how-to-test) and `architecture/` also holds `security/` and `reviews/`. Pick one home for reviews and one for security. Suggestion: `architecture/` for decisions, solution design, threat model and security checklist; `docs/` for runbooks, reviews, research, testing and migrations. Move `architecture/reviews/the 19 Oct EA review` to `docs/reviews/`, where all other dated reviews are. Move `docs/security/checklist-exception-data-deletion.md` into `architecture/security/` next to the checklist it excepts.
2. **Rename for kebab-case** (row 15).
3. **Add a short `docs/README.md`** that lists the subfolders and where the plan and ADR index are. The amplify README links the plan, design and decisions at the bottom, but a person landing in `docs/` has no map.
4. **Keep the workspace README's layout out of marketing-tools' README.** Link to the amplify README as it does now, so the other two apps stay described in their own terms.
5. **Add a `docs/` link check to `make check`.** The Python pass I ran for this review found 0 broken links. A 15-line script in `scripts/` keeps it that way after the renames.
